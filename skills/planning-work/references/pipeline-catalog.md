# Pipeline catalog

Use this catalog when a user asks for a workflow, or when coordinating several agents and a reusable sequence would help. Pick the smallest applicable recipe; do not turn the catalog into a mandatory lifecycle. Each step is a separate skill or source workflow, not a new central runner. This reference ships inside `planning-work` for individual offline installation. Repository paths below are provenance labels, not links or runtime dependencies.

## Authority and selection

- **Local REQUIRED** means an installed skill's own applicable completion/safety condition; it is not a requirement to run every recipe stage. The local planning route selects the smallest applicable set. Skip inapplicable work and state material gaps rather than treating an omitted optional step as failed.
- **Source-required** describes a gate in the named source workflow only. The initial EGM decision rejected mandatory stages, rigid interactive gates and prescribed artifacts as general policy. A later approved review accepted selected adaptations: fresh-context comprehension/readiness perspectives, reader-visible evidence for document feedback, opt-in drift analysis, and this catalog. These local adaptations do not adopt EGM's end-to-end workflow or its external side effects. The EGM workflow itself remains opt-in and applies only when specifically requested.
- A user/repository authority boundary wins over any recipe. Never infer approval for publication, commits, external writes, or destructive changes from a pipeline choice.

Source-only behaviors below describe that snapshot, not installed local policy. Later approved decisions adapt selected review concepts; they do not adopt this full source workflow.

|---|---|---|---|---|
